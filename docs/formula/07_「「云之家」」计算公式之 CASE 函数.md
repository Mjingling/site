# 「「云之家」」计算公式之 CASE 函数

## 一、函数作用

`CASE` 函数用来**根据多个条件判断返回对应的值**，简单来说就是：
- 按顺序判断多个条件
- 返回第一个为真的条件对应的值
- 类似于编程中的 switch-case 或多层 if-else

常用于多等级划分、多条件分类等场景。

---

## 二、语法格式

```
CASE(条件1, 返回值1, 条件2, 返回值2, ...条件N, 返回值N, 默认值)
```

### 参数说明

| 参数 | 说明 | 是否必填 | 示例 |
|------|------|----------|------|
| 条件1, 条件2... | 要判断的条件表达式，按顺序判断 | ✅ 必填 | CASE(分数 >= 90, "优秀", 分数 >= 60, "及格", "不及格") |
| 返回值1, 返回值2... | 对应的返回值，当对应条件为真时返回 | ✅ 必填 | CASE(分数 >= 90, "优秀", 分数 >= 60, "及格", "不及格") |
| 默认值 | 所有条件都不满足时的返回值 | ❌ 可选 | CASE(分数 >= 90, "优秀", 分数 >= 60, "及格", "不及格") |

### 返回值

- 返回第一个为真的条件对应的值
- 如果所有条件都不满足，返回默认值（如果提供）

---

## 三、实用示例

### 示例 1：基本用法

```js
CASE(分数 >= 90, "优秀", 分数 >= 80, "良好", 分数 >= 60, "及格", "不及格")

// 示例数据
// 分数 95 → "优秀"
// 分数 85 → "良好"
// 分数 70 → "及格"
// 分数 50 → "不及格"
```

### 示例 2：成绩等级划分

假设有【成绩表】，包含【分数】字段：

```js
CASE(分数 >= 90, "优秀", 分数 >= 80, "良好", 分数 >= 70, "中等", 分数 >= 60, "及格", "不及格")
```

### 示例 3：销售提成比例

根据销售额确定提成比例：

```js
CASE(销售额 >= 100000, 0.10, 销售额 >= 50000, 0.08, 销售额 >= 10000, 0.05, 0.02)
```

### 示例 4：员工级别划分

根据工龄确定员工级别：

```js
CASE(工龄 >= 10, "高级", 工龄 >= 5, "中级", 工龄 >= 2, "初级", "实习")
```

## 四、实际业务场景

### 场景 1：会员等级划分

根据消费金额确定会员等级：

```js
// 【会员等级】的计算公式
CASE(
  累计消费 >= 100000, "钻石会员",
  累计消费 >= 50000, "白金会员",
  累计消费 >= 10000, "金卡会员",
  累计消费 >= 1000, "银卡会员",
  "普通会员"
)
```

### 场景 2：订单状态判断

根据不同条件判断订单状态：

```js
// 【订单状态】的计算公式
CASE(
  已发货 == "是" && 已签收 == "是", "已完成",
  已发货 == "是", "配送中",
  已付款 == "是", "待发货",
  "待付款"
)
```

### 场景 3：库存预警级别

根据库存数量确定预警级别：

```js
// 【预警级别】的计算公式
CASE(
  库存数量 <= 库存下限 * 0.3, "紧急",
  库存数量 <= 库存下限 * 0.5, "警告",
  库存数量 <= 库存下限, "提醒",
  "正常"
)
```

### 场景 4：绩效等级评定

综合多个维度评定绩效：

```js
// 【绩效等级】的计算公式
CASE(
  综合得分 >= 90, "S级",
  综合得分 >= 80, "A级",
  综合得分 >= 70, "B级",
  综合得分 >= 60, "C级",
  "D级"
)
```

## 五、常见问题

### ❓ 参数个数有限制吗？

参数必须是奇数个（条件和值成对出现，最后一个是默认值）。也可以不提供默认值（偶数个参数），此时不匹配返回空。

```js
// ✅ 正确：奇数个参数（带默认值）
CASE(条件1, 值1, 条件2, 值2, 默认值)  // 5个参数

// ✅ 正确：偶数个参数（没有默认值）
CASE(条件1, 值1, 条件2, 值2)  // 4个参数

// ❌ 错误：条件和值不匹配
CASE(条件1, 值1, 条件2)  // 3个参数，缺少条件2对应的值
```

### ❓ 如果没有默认值会怎样？

如果所有条件都不满足，返回**空**。

```js
CASE(分数 >= 90, "优秀", 分数 >= 80, "良好")

// 如果分数是70，既不>=90也不>=80，返回：空
```

### ❓ 条件顺序重要吗？

非常重要！CASE 按顺序判断，返回第一个为真的值。

```js
// ✅ 正确顺序：从高到低
CASE(分数 >= 90, "优秀", 分数 >= 60, "及格", "不及格")
// 分数95：先判断>=90（真），返回"优秀"

// ❌ 错误顺序：从低到高
CASE(分数 >= 60, "及格", 分数 >= 90, "优秀", "不及格")
// 分数95：先判断>=60（真），返回"及格"（不会继续判断>=90）
```

### ❓ 可以嵌套使用吗？

可以，但不推荐。建议用多个条件替代嵌套。

```js
// ✅ 推荐：使用多个条件
CASE(
  分数 >= 90 && 出勤率 >= 90, "优秀",
  分数 >= 80 && 出勤率 >= 80, "良好",
  分数 >= 60, "及格",
  "不及格"
)

// ❌ 不推荐：嵌套CASE
CASE(
  分数 >= 90, CASE(出勤率 >= 90, "优秀", "良好"),
  分数 >= 60, "及格",
  "不及格"
)
```

## 六、搭配使用技巧

### 技巧 1：结合数学运算

```js
// 根据销售额计算实际提成
销售额 * CASE(销售额 >= 100000, 0.10, 销售额 >= 50000, 0.08, 0.05)
```

### 技巧 2：组合多个条件

```js
// 综合分数和出勤率
CASE(
  分数 >= 90 && 出勤率 >= 90, "优秀",
  分数 >= 80 && 出勤率 >= 80, "良好",
  分数 >= 60 || 出勤率 >= 80, "及格",
  "不及格"
)
```

### 技巧 3：返回不同类型的值

```js
// 根据条件返回不同格式
CASE(
  状态 == "完成", "✓ 已完成",
  状态 == "进行中", "→ 进行中",
  状态 == "未开始", "○ 未开始",
  ""
)
```

### 技巧 4：动态计算

```js
// 根据会员等级计算折扣后价格
原价 * CASE(
  会员等级 == "钻石", 0.7,
  会员等级 == "白金", 0.8,
  会员等级 == "金卡", 0.9,
  1
)
```

## 七、与 IF 函数的区别

| 函数 | 适用场景 | 示例 |
|------|---------|------|
| IF | 简单的二选一判断 | IF(分数 >= 60, "及格", "不及格") |
| CASE | 多个条件的复杂判断 | CASE(分数 >= 90, "优秀", 分数 >= 80, "良好", 分数 >= 60, "及格", "不及格") |

**选择建议**：
- 只有2个结果 → 用 IF（更简洁）
- 有3个或更多结果 → 用 CASE（更清晰）
- 需要嵌套IF → 用 CASE（避免嵌套）

**对比示例：**

```js
// 使用嵌套IF（不推荐）
IF(分数 >= 90, "优秀",
  IF(分数 >= 80, "良好",
    IF(分数 >= 60, "及格", "不及格")
  )
)

// 使用CASE（推荐）
CASE(分数 >= 90, "优秀", 分数 >= 80, "良好", 分数 >= 60, "及格", "不及格")
```

## 八、注意事项

### ⚠️ 条件顺序非常重要

务必按照从严格到宽松的顺序排列条件：

```js
// ✅ 正确：从高到低
CASE(分数 >= 90, "优秀", 分数 >= 60, "及格", "不及格")

// ❌ 错误：从低到高会导致高分也被判为及格
CASE(分数 >= 60, "及格", 分数 >= 90, "优秀", "不及格")
```

### ⚠️ 参数必须成对出现

每个条件必须有对应的返回值：

```js
// ✅ 正确
CASE(条件1, 值1, 条件2, 值2, 默认值)

// ❌ 错误：条件2没有对应的值
CASE(条件1, 值1, 条件2, 默认值)
```

### ⚠️ 默认值的使用

建议总是提供默认值，避免意外的空值：

```js
// ✅ 推荐：有默认值
CASE(分数 >= 90, "优秀", 分数 >= 60, "及格", "不及格")

// ⚠️ 不推荐：没有默认值，可能返回空
CASE(分数 >= 90, "优秀", 分数 >= 60, "及格")
```
